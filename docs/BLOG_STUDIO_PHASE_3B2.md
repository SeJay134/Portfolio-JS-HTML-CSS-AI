# Phase 3B.2 — draft persistence client

Stacked on #53. Phase 3B.1 exact head a09b4938d12ba3aa3ff123b7462623b41f1a3a0d passed all four push/PR workflows: 92 SQL assertions, 45 real local Data API checks, 202 unit tests on Linux and Windows, four Studio browser tests. Vercel Preview is rate limited. No hosted changes.

VITE_ENABLE_BLOG_DRAFTS is a separate opt-in (default off, local OAuth launcher true), subordinate to the editor and Google admin gates. The original memory-only mode remains available and separately tested. Private RPCs load up to 20 documents sequentially, validating exact structured v1 content, IDs, metadata, limits and conservative links. No direct table access, local/session storage drafts, secrets or publishing. Server remains authoritative.

Manual Save draft and optional 15-second idle autosave; serialize one request at a time and disable editing during save/reload/restore. A response must match the ID/revision expected. Network/timeout errors stop autosave for that draft, retaining the same immutable request/key for explicit retry; newer edits are saved only after confirmation. Conflict errors stop writes until explicit reload (confirmation warns of unsaved loss); no force overwrite. Server validation or quota errors are visible, raw server details not displayed. Saved versions load on remount after the existing fail-closed authorization recheck. A denial aborts outstanding requests and clears local draft state. Do not rely on abort to roll back a committed request. Explicit reload retrieves the latest state. Unsaved edits can still be lost during gate rechecks, refresh, logout or pagehide; beforeunload warning where browser supports it.

Revision history read and restore previous document as a new unsaved edit (save creates a new immutable revision). Retention: existing hard 100 revisions/draft, 20 drafts, 20 MiB total history per owner; no automatic purge or destructive saved deletion. Long-running use requires an independently reviewed retention/deletion policy, efficient autosave coalescing and quota tests before production. Category/tags are draft text only until taxonomy/publication work. No new dependencies or migrations. Real OAuth and physical-device checks deferred to final isolated acceptance, not waived. No merge or production activation.

Tests: repository decoder and RPC behavior, original memory-only Studio browser suite and a separate persistence-enabled compiled mock RPC browser suite (desktop Chromium and mobile WebKit). The Phase 3B.1 real SQL/API tests independently cover actual local backend. No claim that mocked browser tests are real hosted OAuth.
