# Phase 3D.1 — private media quarantine foundation

Stacked on #55. Generated migration filename with pinned Supabase CLI 3.4.0 in a disposable GitHub Actions runner. No hosted operations. Both buckets private, JPEG MIME and 5,000,000 byte object caps. See https://supabase.com/docs/guides/storage/security/access-control and https://supabase.com/docs/guides/storage/schema/design. Bucket metadata is configured by migration, actual objects are managed only through Storage API.

Private metadata table has RLS/no client grants; reserve RPC is invoker over a non-exposed narrowly authorized function. Server derives owner from current live Google admin and fixed path from owner UUID + asset UUID. Reservation expires after one hour, idempotent for same active owner/id; 20 slots per owner (100 MB worst-case quarantine allocation), including expired/rejected slots until reviewed cleanup. Client upload only exact owned reserved quarantine path; no upsert, select, public read, signed URL, update, delete, direct verified write or client state transition. Restrictive policies block accidental permissive-policy exposure and leave unrelated buckets unaffected. No frontend flag or UI upload added. No service key added.

Quarantine is untrusted, even if MIME claims JPEG. This increment intentionally does NOT validate image bytes, mark assets ready, decode/re-encode on a server, issue downloads, attach to drafts, create covers/galleries, or promote objects. Phase 3D.2 must select a pinned supported server decoder, independently bound decode/dimensions/bytes, normalize and validate output, recheck live auth and object identity, implement idempotent promotion and orphan/expiry cleanup via Storage API, verify server-only credentials and costs. Separate reference model and editor integration after that. Never expose these buckets publicly or enable upload UI until promotion and cleanup tested. No production merge/activation.

Tests: SQL role/auth/path/idempotency/quota/revocation and real local Storage API with synthetic safe JPEG, anonymous/ordinary/direct/overwrite/download/signing negatives. Tests must complete before acceptance; no physical iPhone testing or actual hosted OAuth required here. Original Phase 2F readiness gates remain open.
