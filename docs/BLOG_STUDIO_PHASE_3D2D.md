# Phase 3D.2D — local broker and expiry cleanup

Stacked on #59, whose exact head passed 93 real local API checks. Migration filename allocated by pinned local CLI. No hosted changes.

The authenticated invoker RPC returns only a trusted grant context (not a JWT) for the current live Google admin's exact owned asset, session, action and expiry bounded by the original token and 120 seconds. It cannot issue a signing credential. The Python broker forwards the actual user token to the local Data API and validates the returned context before invoking an injected trusted signer. It never reads a signing secret, accepts arbitrary origins, returns a capability to browser or exposes an endpoint. CI alone signs disposable HS256 tokens; no production signer is implemented or configured. Do not put the project JWT signing key in a public/runtime function or assume this interface is a security boundary against a compromised signer.

Explicit promote vs cleanup claims. Expired reserved assets can be fenced into rejected only after 15-minute grace, under row lock. Only the exact rejected asset can then be removed from both private buckets via Storage bulk delete. Cleanup capability cannot download, commit, sign, overwrite or delete any verified asset. Promotion worker cannot delete a rejected verified-bucket orphan. Tombstones stay private and count toward quota; no ID reuse, quota release, scheduled cleanup or guarantee against indefinitely delayed in-flight writes. Repeat cleanup is safe for exact rejected keys, but eventual consistency/orphan reconciliation and bounded quota reclamation must be tested separately before real usage. Verified quarantine cleanup from 3D.2B unchanged. No direct storage.objects mutation.
