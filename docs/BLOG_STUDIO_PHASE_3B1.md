# Phase 3B.1 — private working-copy foundation

Stacked on #52. Local/CI only. The migration filename was generated by Supabase CLI 3.4.0 in a read-only GitHub Actions runner; no remote connection or migration was applied. The isolated OAuth launcher copies the reviewed fourth migration. No new dependency, actual user, secret, hosted setting, upload, deployment or publication.

Working copies use private.studio_drafts and immutable-by-client private.studio_draft_revisions (RLS on, no direct grants or exposed schema). Narrow public invoker RPCs delegate to fixed-search-path blog_internal functions; each verifies current live Google admin authorization and derives owner from auth.uid(). Even another admin cannot access another owner's copies. Public list/read and projection stay unchanged. Server validates the exact v1 structured editor document, byte/field/block/run limits, slug, duplicate block IDs, safe conservative URL subset. Rich HTML is not accepted as structure; text is rendered escaped by 3A. Empty drafts are allowed. JSONB serialized size is the server limit, so whitespace overhead may differ from JS serialization.

Save uses expected revision, serialized transaction/owner quota locks and idempotent per-draft request UUID. Replaying exact request returns original revision; reusing key with different body/version fails. Conflicting update never silently overwrites. Every successful new save creates an immutable revision and working copy atomically; get supports historical read. A restore will be a new save, not revision mutation. Empty slug allowed; nonempty draft slug unique in working-copy store. Cross-projection slug reservation and existing public-table direct admin mutation restrictions are mandatory before publication (3E); this migration does not change those existing policies.

Provisional conservative limits: 20 drafts per owner, 100 revisions per draft, 20 MiB total serialized revision documents per owner, 1 MiB per document. No automatic history deletion or actual paid-capacity claim. Limit reached returns error; 3B.2 must expose this clearly and implement reviewed retention/discard/restore lifecycle before long-running autosave. No UI persistence in 3B.1; it is intentionally a backend-only increment. No local manual test required for this increment if CI passes; full real OAuth and physical device acceptance remains deferred to final isolated staging review. Full original Phase 2F production gates remain open.

Tests: pgTAP role/RLS/validation/CAS/replay/history/revocation/cross-owner; real loopback PostgREST synthetic JWT integration. Existing 3A and legacy public API regressions remain. CI results must be verified on exact head before follow-up; no production rollout approved.
