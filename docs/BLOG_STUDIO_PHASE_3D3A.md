# Phase 3D.3A — local Studio photo upload

Stacked on #61. Only explicit --media launcher mode enables the upload flag. Browser additionally requires Vite DEV, exact oauth-staging mode, exact 127.0.0.1:5511 app and 54321 API origin. Fixed 5512 local service. No hosted fallback, credentials in URLs, worker capabilities in browser, or new dependencies. No schema change. Production builds never enable this path even if flag is set.

Only existing screened/ready JPEGs can be sent through the UI, after confirmation. One upload at a time. The user session token authorizes an exact UUID reservation; response must match the current owner and expected object key. Upload raw JPEG to private quarantine (no upsert); then POST only asset ID and selected byte cap to local service. Verified receipt validated by ID, dimensions, byte cap and SHA-256 format. Client cannot establish semantic content safety or bypass server authorization: existing on-device screening is advisory and direct admin uploads can still bypass it; server only validates JPEG bytes. No public assets.

Uncertain results can be explicitly retried using the same UUID: first reconcile via idempotent promote, then reserve/upload if appropriate. Never silently generate another ID or overwrite. Cancellation aborts client requests, not necessarily committed server work. Queue and temporary receipts are in memory, discarded on auth recheck/unmount, no browser persistent image data. Clear/remove only clears local queue, not private objects. Hard 20-slot quota (including tombstones); no quota reclamation. No persistent asset listing, verified photo viewer, image block/cover/gallery reference or publication yet. These follow in a separate increment, along with hosted issuer/hosting review and cleanup lifecycle. No merge/production changes.

Tests exercise actual client request shape, exact origin gate, receipt and reservation validation, retries and wrong response, plus UI local upload button with mocked service. Existing PR #61 real API suite verifies the independent HTTP/backend pipeline. No full real Google or physical device acceptance yet.
