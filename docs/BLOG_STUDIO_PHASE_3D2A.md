# Phase 3D.2A — server JPEG validation primitive

Stacked on #56. At review, 113 SQL assertions and 63 real local API checks passed, including real reserved quarantine upload, public/signed read denial and revoked-session denial. Parent final browser regression still running. No hosted changes or production authorization.

This increment provides a server-side byte-only worker and adapter, not an HTTP endpoint or Storage promotion path. Dedicated CPython 3.12 environment and Pillow 13.0.0 pinned to two trusted PyPI wheel hashes (Linux x64 glibc and Windows x64); no modifications to existing Python AI or npm dependencies. References: https://pypi.org/project/pillow/13.0.0/ and https://pillow.readthedocs.io/en/stable/handbook/security.html. Install in isolated environment only. CI tests real decode/encode on both platforms.

Validate input <=5,000,000 bytes. Structural preflight accepts a conservative subset of JPEG (baseline/progressive Huffman, 8-bit, 1/3 channels, max side 2200, single frame, bounded segment/scan counts, no bytes after EOI). No parser for other formats. Verify and fully decode; copy RGB pixels into a fresh image, discard metadata and re-encode baseline JPEG with bounded quality attempts; output must meet selected 20,000–5,000,000 byte cap or fail; no resizing in this layer. Browser already orients images; arbitrary source EXIF orientation/ICC not preserved. Adapter computes final SHA-256 and dimensions; rejects mismatched/oversized result and process failure. Normalization can change quality; keep explicit selected target for later integration. JPEG structural and pixel verification is not semantic moderation or a proof that all steganography or malicious decoder inputs are impossible.

Worker subprocess has 12-second wall timeout and Linux CPU/address-space limits, sanitized inherited environment, fixed executable/script path, no network code, no secrets, no raw image/decoder logs. Windows does not have Linux resource limits. This is not a complete OS sandbox: before a network-facing implementation, verify sandbox/no-egress and filesystem controls, bounded concurrency/output, vulnerability audit of native codec/wheels and deployment runtime. Do not run this in the existing AI process. No hosted service added and no additional recurring charges incurred by design.

No client verification, no public route, no upload UI, no actual object promotion in this PR. All buckets stay private. Do not merge or enable hosted features. Manual real OAuth and physical-device acceptance remain deferred, not waived.
